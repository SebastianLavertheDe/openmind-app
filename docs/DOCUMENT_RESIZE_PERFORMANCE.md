# 长文档实时分栏

分割线始终实时改变两侧宽度，Markdown/纯文本随之换行。PDF 保留固定版式，实时缩放当前页面；停止变化后补充高清画布。没有使用拖动占位线或松手后才更新布局。

## 渲染边界

- `ColumnSplitter` 将同一动画帧内的指针事件合并；松手提交最后一段位移，Escape/失焦取消。
- `AiWorkbench` 拖动期间直接更新 Grid 的 CSS 变量，结束时才保存 React 中的比例。正文解析不依赖宽度。
- `DocumentReader` 使用完整文档模型。超过 16 Ki 字符的 Markdown 在可终止的 Worker 中完成解析；引用、脚注和表格规范化按整篇处理。
- TanStack Virtual 只挂载可见块和少量预读块。长段落、代码和表格单元格进一步分段，常规文本块预算为 1024 字符；不可拆开的公式保持原子布局。缩放使高度缓存失效时，重新测量已挂载块，并保留原阅读段落。
- 搜索和复制读取完整模型，不依赖屏幕外 DOM。选择的起止块保持挂载，文件的 AI 选中引用使用同一文本映射。全文搜索入口为阅读器内 `Ctrl/Cmd+F`。
- 长聊天正文使用同一阅读器；超长流式输出复用已完成的纯文本块，仅更新尾块。历史对话原有的分页、过程展开状态和滚动跟随逻辑保持不变。
- 文件编辑复用 CodeMirror 的可见区域渲染，不再将整篇文件交给 textarea。
- PDF.js 官方 Viewer 管理分页、文字层、查找和画布缓存。每份文档拥有自己的 Worker，关闭时释放，避免快速重开与旧任务销毁竞争。

## 可复现验收

```sh
npm run perf:documents
```

脚本构建独立的生产模式夹具，加载实际阅读器、分割线和完整应用样式，在真实 Electron 中发送鼠标事件。只使用合成内容和临时 userData，不访问用户数据仓库。输出目录包含 JSON 报告、截图；设置 `OPENMIND_DOCUMENT_PROFILE=1` 可额外保存 CPU profile。

断言包括：松手前栏宽和正文几何连续变化、父组件不逐帧重渲染、挂载文本块/画布有上限、空闲不持续执行脚本、拖动帧间隔 P95 < 50ms、屏幕外全文搜索/全选、阅读段落保持、相邻块不重叠、PDF 末页定位/搜索以及关闭重开。

2026-09-11 验证环境：Linux ARM64、Electron 42.8.1、1600×1000、Xvfb、软件渲染。10 / 200 / 500 页均覆盖。200 / 500 页 Markdown 合成文本分别约 27.5 / 68.8 万字符；PDF 每页包含 24 行合成文本。

| 样本 | 拖动后挂载量 | 拖动帧间隔 P95 |
| --- | --- | --- |
| 200 页 Markdown | 9 个文本块 | 约 16.7ms |
| 500 页 Markdown | 9 个文本块 | 约 16.7ms |
| 200 页 PDF | 4 张画布 | 约 16.8ms |
| 500 页 PDF | 4 张画布 | 约 16.8ms |

这些数据验证长文档不会按全文规模参与每帧排版，不代表所有机器、复杂扫描件或任意公式的帧率保证。首次解析、搜索全文和非可见块的高度估算仍可能随文档长度增长；它们不在逐帧正文解析路径中。PDF 页占位元素数量仍与页数相关，实际画布/文字层按官方可见范围队列渲染。

文件读取层原有的大小限制没有改变；该性能夹具直接向实际阅读组件提供完整合成文档，未通过截断内容取得上述结果。

完整回归曾得到 1846 通过、1 失败、3 跳过；随后补充的文档/代码复制测试单独通过。唯一失败是 `InstalledSkillExecutionResolver` 的 Reddit → Article Summary → Topic 链路，错误为 `daily-article-summarizer did not render the deterministic article summary`。在 `6ab0f17` 的独立原始代码副本上复现了相同失败，不属于本次渲染改造。构建、隔离集成测试和真实 Electron 启动测试通过。

相关回归测试位于 `renderer/src/components/document/`、`ColumnSplitter.test.tsx` 和 `PdfMaterialViewer.test.tsx`。
