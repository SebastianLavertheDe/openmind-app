# RSS 源卡片与分类 Tab 实施计划

日期：2026-10-27（Asia/Shanghai）  
状态：待实施。本文件定义改造方案，本次仅编写计划。

## 1. 目标和页面结构

把「设置 → RSS 源」的长行列表改成卡片网格，沿用 Skills 页的分类 Tab、搜索、筛选与卡片视觉语言。用户可以按分类浏览订阅，快速辨认启停状态、RSS 是否就绪、文章采集是否失败，并在卡片上完成常用操作。

页面自上而下排列：

1. 设置页现有标题与说明，避免内层再渲染一次标题。
2. 搜索框与「添加源」「导入 OPML」「刷新」。
3. 胶囊分类 Tab：全部、博客与网站、公众号、其他已有分组、未分类。
4. 结果数、状态筛选与排序。
5. 全局任务操作：更新 RSS、采集文章、更新并采集、定时任务、运行记录、总结与选题偏好。
6. RSS 源卡片网格；无匹配结果时提供清除筛选入口。

参考实现为 `renderer/src/features/skills/SkillLibraryPage.tsx`，复用其 `Tabs variant="pill"` 和网格组织方式。RSS 卡片采用紧凑的信息布局，优先容纳状态与操作；不增加大幅装饰封面。卡片表面使用现有 `workspace-card` 及设计令牌。

## 2. 分类规则

首版以现有 `RssSource.group` 为分类依据。公开目录目前只有 `blog` 与 `WeChat` 两类，实际订阅还可能来自历史配置或 OPML 分组；不能根据截图中的数量硬编码分类或计数。

| 分组值 | Tab 名称 | 处理方式 |
| --- | --- | --- |
| 虚拟 `all` | 全部 | 包含当前内容根中的所有源 |
| `blog` | 博客与网站 | 仅映射显示名称，保留存储值 |
| `WeChat` | 公众号 | 仅映射显示名称，保留存储值 |
| 其他非空值 | 原分组名称 | 动态生成 Tab，保留 OPML 与用户已有分组 |
| 空值或纯空白 | 未分类 | 保证新增、导入及历史源都有入口 |

- Tab 使用带命名空间的内部 ID，区分虚拟「全部」「未分类」与用户恰好同名的真实分组。
- 展示顺序：全部 → 博客与网站 → 公众号 → 其他分组按名称排序 → 未分类。没有源的分组不显示。
- Tab 显示数量。数量应用当前搜索和状态筛选，但不应用当前选中的分类；网格结果数再应用分类，二者口径明确。
- 搜索覆盖名称、完整原始地址、标签及分组；分类、搜索、状态同时生效。
- 切换分类保留搜索、状态与排序。删除或移动最后一个源导致当前分类消失时，回到「全部」。
- 本期不凭名称自动给源贴 AI、金融、设计等主题标签。如后续需要主题分类，应独立制定分类目录和映射，避免混淆现有来源分组。

新增及编辑源的表单增加「分类」选择，使用共享 `Select`，可选已有分组与未分类；已有自定义分组必须原样保留。首版不增加独立的分类创建、合并、删除管理器。

## 3. 卡片内容与操作

| 区域 | 内容与行为 |
| --- | --- |
| 顶部 | RSS/分类图标、源名称、启停开关。名称最多两行，完整名称保留可访问名称 |
| 地址 | 原网站或 RSS 地址，显示主机与必要路径；完整 URL 可访问、可复制，点击经现有 `openExternal` 打开 |
| 分类 | 当前分组标签；不堆叠全部搜索标签 |
| RSS 状态 | 尚未生成 / 需要更新 / 已就绪，以及最近 RSS 成功更新时间、Feed 文章条目数 |
| 采集异常 | 独立显示正文采集失败摘要；不把 Feed 失败和正文失败混成一个状态 |
| 底部 | 「更新并采集」按钮，以及编辑、更多操作。删除放入共享菜单，继续使用确认弹窗 |

- 文章条目数来自 `itemCount`，标签为「RSS 条目」，不称为「已采集文章数」。
- 本地转换地址同时在详情概览与编辑源弹窗中展示，保留完整路径、只读、换行和就绪说明。
- 点击卡片主体（图标、名称及信息摘要）打开该源的详情弹窗。主体使用独立、可键盘激活的选择按钮，开关、原网址和底部动作是其兄弟节点；不在整个 `article` 上绑定点击，也不把控件嵌套进按钮。
- 底部操作对齐；错误摘要限制为两行。「查看详情」同样打开该源详情并定位到错误说明，避免再维护一个独立错误弹窗。
- 更新并采集仅对当前卡片的源执行，传递 `sourceId`。停用或缺少原始地址的源不允许执行。
- 编辑、删除、启停保留现有修订冲突校验、未保存修改保护和操作后的刷新行为。

### 3.1 点击卡片后的详情弹窗

与 Skills 卡片一致，展开为居中的大尺寸 `Dialog`，窄容器内保持安全边距、内容区滚动、页头和底部操作可达。使用 `DialogHeader`、`DialogBody`、`DialogFooter`；首次打开默认进入「概览」，不直接进入可编辑表单。

弹窗结构：

| 区域 | 内容 |
| --- | --- |
| 页头 | 源图标、完整名称、分类、启停状态、关闭按钮 |
| 内部 Tab | 概览、RSS 条目、运行记录 |
| 可滚动内容 | 当前 Tab 的内容；加载中、空态、错误均在对应区域呈现 |
| 底部 | 编辑源、更多操作，以及主按钮「更新并采集」 |

**概览 Tab**

- 基本信息：名称、分类、标签、原网站或 RSS 完整地址。链接可打开、可复制。
- 地址关系：若存在 `resolvedFeedUrl`，单独显示「识别出的 RSS 网址」；本地 XML 显示「采集使用的本地 RSS 文件」，提供复制。三类地址有明确标签，不让用户把文件路径当成可在外部浏览器访问的订阅网址。
- RSS 状态：本地文件是否存在、是否需要更新、最近 RSS 成功更新时间、RSS 条目数。尚未生成时显示原因和「更新 RSS」入口。
- 最近尝试：尝试时间和阶段；发生错误时先给可读摘要，下面通过共享披露控件展开错误码与原始消息。保留「RSS 已就绪，但正文采集失败」的并列状态。
- 操作入口：启停、检测链接、单独更新 RSS、采集文章。检测必须实际解析出文章，但检测结果只表示这次验证，不改写更新时间、不假装已生成本地 XML。
- 「采集文章」仅在启用、有地址且当前 XML 就绪时可执行；尚未生成或过期时提示先更新 RSS。批量页面现有能力不受这一单源快捷入口影响。

**RSS 条目 Tab**

- 显示本地转换 RSS 中的文章索引：标题、发布时间、原文链接。默认最新在前，无日期项放在最后且显示「日期未知」。
- 名称明确为「RSS 条目」，不称为「已采集文章」。有条目只说明解析得到文章索引，不代表正文已经成功保存。
- 本地文件尚未生成时给出更新入口；读取或解析失败时显示局部错误与重试，不能导致整个详情打不开。
- 使用分页，每页 30 条；按需读取，避免将 OpenAI 等上千条索引一次性塞入详情。仅打开详情或切换 Tab 不联网、不自动触发更新或采集。
- 如果当前文件已过期，保留条目可读，并显著标注「旧 RSS 条目，需更新」。后台文件刷新后重置分页并读取新版本，避免页码与内容错位。
- 首版点击文章打开原文，不增加文章全文阅读器或推断正文已保存的徽标。

**运行记录 Tab**

- 展示涉及当前源的最近运行，默认最近 20 条，可加载更多。包含任务类型、时间、状态、该源的更新条目数/采集数量，以及失败阶段。
- 对批量任务，必须从结果中定位当前 `sourceId` 的结果；批量任务整体成功或失败不能直接当作当前源结果，也不能只按 `rss-article-saver` 的 Skill ID 筛选。
- 如任务尚在执行且没有单源结果，只显示可证实的任务进度；不虚构“已采集成功”。没有记录时显示空态。
- 可进入现有运行详情查看完整日志；从运行详情返回时保留该源的详情上下文。

### 3.2 详情、编辑与卡片之间的流转

1. 点击主体 → 打开只读详情；页面分类、查询、筛选、排序与滚动位置保留。
2. 点击详情里的「编辑源」→ 在同一弹窗流程切换为编辑模式，避免叠两个大弹窗。卡片快捷编辑可直接进入编辑模式。
3. 从详情进入编辑后，取消或保存均回到该源概览；未保存修改需要确认。由卡片直接编辑时，取消或保存回到卡片页。
4. 检测、更新和采集分别显示自己的请求状态。任务提交后详情保持打开，轮询更新状态，不关闭弹窗、不打断阅读。
5. 删除成功后关闭详情，保留原页面筛选并将焦点移到相邻卡片或结果标题。其他入口删除了当前源时，提示「该源已被删除」，不能继续对陈旧对象执行操作。
6. 关闭详情回到原卡片主体按钮；若编辑分类后卡片已不在当前筛选中，焦点回到结果区域。正文内容滚动不影响底部操作。

### 3.3 详情所需数据与访问边界

概览沿用 `RssSourceView`，按源 ID 绑定最新数据，而不是持有打开时的陈旧对象。仅 RSS 条目与按源运行记录需要补充有界的查询能力：

- 为读取本地条目增加类型化 preload IPC，例如 `getRssSourceEntries({ sourceId, cursor?, limit })`。Main 根据当前内容根和源 ID 推导文件位置，校验路径、文件大小、XML 安全及条目字段；renderer 不能传入任意文件路径。
- 返回只包含文章索引的分页视图、总数、文件版本及过期标记，不返回全文，也不持久化重复索引。文件版本变化后旧游标失效，前端回到第一页。
- 为运行记录复用已有查询能力；如现有接口只能返回全部运行，则扩展为按当前内容根、源 ID 和游标的有界查询，不能先向 renderer 传全部日志再筛选。跨内容根数据不得混入。
- 查询失败只影响对应 Tab；快速切换源、关闭详情或切换内容根后丢弃过期响应。非当前 Tab 的重型数据不轮询，详情关闭后停止详情查询。
- 所有路径操作、XML 解析和 RunStore 查询留在 Main/已有后端模块。长路径复制复用 `CopyButton` 或 `useClipboard`，弹层与披露行为复用共享组件。

## 4. 状态呈现与错误文案

状态由现有 `localFeed.status`、`lastError.stage`、`lastError.code`、`feedRevision`、`revision` 等字段推导，不以是否存在错误作为 Feed 可用性的唯一依据。

| 数据情况 | 卡片呈现 |
| --- | --- |
| 本地 XML 不存在 | RSS：尚未生成 |
| XML 存在但修订不匹配 | RSS：需要更新 |
| XML 存在且修订匹配 | RSS：已就绪 |
| `stage=sync` | 补充「RSS 更新失败」；若保留旧 XML，仍展示旧文件事实，不能声称本次更新成功 |
| `stage=collect` 且 XML 就绪 | 同时展示「RSS 已就绪」与「正文采集失败」 |
| `stage=configuration` | 待配置，提供编辑入口 |
| 停用且仍有历史错误 | 开关显示停用，错误明确为上次运行结果，不伪装成当前运行中 |

示例：OpenAI 的 Feed 已成功解析、正文请求被拒绝时，显示「RSS 已就绪 · 正文访问被拒绝」，而不是只在 RSS 链接下显示 `access-denied`。

`access-denied` 的用户文案不直接推断需要登录或 Cloudflare 验证；只有存在对应响应证据时才作具体说明。没有最近采集成功记录的字段时，不从「没有错误」推断正文采集成功。本期不扩展抓取方式或解决网站验证拦截。

## 5. 筛选、排序及全局操作范围

- 状态筛选：全部、已启用、已停用、异常、待配置；「待配置」对应缺少原始地址或配置阶段错误，不包含普通的尚未更新。
- 排序：默认顺序、名称、最近 RSS 更新。默认保持现有源顺序；同值时用源 ID 保持稳定。
- 结果区展示「当前结果数 / 总源数」。所有计数来自当前内容根的实际配置。
- 全局「更新 RSS」「采集文章」「更新并采集」保持现有全部启用源的执行语义，并明确标注「作用于全部已启用源」。搜索或切换分类不改变执行范围。
- 卡片操作的请求状态按源 ID 管理；提交任务与任务完成分开呈现。IPC 返回任务提交成功只提示「已提交」，不立即将卡片标记为采集成功。
- 保留现有轮询和页面卸载保护。轮询刷新不能清空筛选、编辑内容或无故改变网格顺序；不能每五秒播报全部卡片。

## 6. 响应式和可访问性

- 使用容器可用宽度决定列数，参考 Skills 的 `auto-fill/minmax` 网格。RSS 卡片目标最小宽度约 280px，空间不足时退为单列。
- 在设置主区域、独立页面及 Skill 内嵌来源配置三个入口分别验证布局；宽屏通常为三到四列，中等宽度两列，窄容器一列。
- 分类 Tab 独立横向滚动，不能撑宽整页；键盘切换时选中项保持可见。
- 卡片使用语义化 `article`；标题、开关、图标按钮具有包含源名称的可访问名称。
- 复用共享 Tabs 的键盘与焦点行为，状态同时用文字和色彩表达。详情关闭、编辑取消、删除确认退出后有合理焦点恢复。
- 浅色、深色主题遵循现有令牌。全部应用 CSS 放在 `renderer/src/styles/`；功能样式只负责布局和卡片结构，不能覆盖共享控件的内部外观。

### 6.1 动效：以 Skills 页现有行为为验收参照

RSS 的卡片、分类和展开详情必须与 Skills 页保持一致。实施时并排验证两个页面的实际表现；时长和曲线由现有共享组件及令牌统一提供，不能在 RSS 功能 CSS 中另写一套近似值。

已核对的源码基准：

- `SkillLibraryPage.tsx`：卡片主体使用 `data-motion="selection"`，分类使用 `Tabs variant="pill"`，详情使用共享 `Dialog size="lg"`。
- `styles/components/dialogs.css`：遮罩淡入淡出；面板进入时由 `translateY(6px) scale(.985)` 到正常位置，退出时至 `translateY(4px) scale(.985)`，均伴随透明度变化。
- `styles/components/selection.css`：胶囊 Tab 使用共享选中背景连续滑动，随标签宽度调整；文字颜色同步过渡。开关由共享滑块位移反馈。
- `styles/final-polish.css`：selection 按压保持容器几何稳定；卡片沿用公共表面过渡。
- 当前令牌：`--dur-instant=80ms`、`--dur-fast=140ms`、`--dur-normal=200ms`、`--dur-slow=240ms`、`--dur-exit=160ms`。详情弹窗实际进出场均使用 `--dur-exit`；进入曲线为 `--ease-standard`，退出为 `--ease-exit`。数值仅记录当前基准，代码应复用组件/令牌。

| 交互 | RSS 需要实现的动效 | 实现归属 |
| --- | --- | --- |
| 卡片悬停、聚焦、按压 | 对齐 Skills 的公共卡片表面和 selection 反馈；主体按压保持位置与尺寸稳定，键盘聚焦可见 | 公共卡片样式、`data-motion="selection"` |
| 点击卡片展开 | 同 Skills 详情：遮罩淡入，面板轻微上移并缩放至正常尺寸；打开后焦点进入详情 | 共享 `Dialog`，沿用现有 CSS |
| 关闭详情 | 面板与遮罩按共享退出曲线退场，保留内容直到退场完成；恢复卡片焦点 | `Dialog` / `useExitPresence`，单一生命周期 |
| 分类 Tab 切换 | 与 Skills 相同的胶囊选中背景连续滑动，宽度随标签变化，文字颜色同步过渡；滑动采用 `--dur-normal` 与 `--ease-standard`。结果立即响应选择，不逐卡排队入场 | 共享 `Tabs variant="pill"` |
| 详情内部 Tab | 沿用共享 Tabs 的选择反馈，页头、页脚与遮罩保持稳定；只更新内容区域 | 共享 `Tabs`，功能负责面板状态 |
| 详情到编辑、保存返回 | 保持同一个弹窗外壳，切换内容和操作，不重复播放整层开关动画；保存结果及时可见 | 详情/编辑状态机，共享 `FormDialog` 组成能力 |
| 展开技术错误 | 高度和透明度沿用共享披露动效，收起期间内容不可交互 | 共享 `AnimatedDisclosure` |
| 启停、菜单、动作提交 | 滑块、菜单进出、按钮按压与加载图标均使用 Skills 同款共享控件反馈 | `ToggleSwitch`、共享菜单、`Button` / `IconButton` |
| 轮询、分页、筛选结果更新 | 保留稳定源 ID；只更新发生变化的数据，不重播全部卡片和弹窗的入场动效 | 功能数据更新与稳定 React key |

当前 Skills 详情使用独立弹窗进出场，没有从卡片位置连续形变到弹窗的共享元素动画。RSS 本期以这套已存在的动效为准；同样，分类结果不额外增加卡片飞入、逐项延迟或网格弹簧重排。这样长列表和高频搜索仍保持与 Skills 相同的响应节奏。

### 6.2 动效生命周期、性能和减少动态效果

- Dialog 保持挂载，使用 `open` 控制显隐；退出时由共享组件保留最后内容快照。不能在 `open=false` 的同一帧条件卸载整个详情，造成退场消失或空白闪屏。
- 每个浮层只有一个进出场管理者。沿用共享 Dialog 的 presence，不再在外层包第二套 `AnimatePresence`、手写定时器或重复遮罩动画。
- 以 `opacity`、`transform` 为弹窗运动属性；卡片列表不逐帧测量几何，不给 200+ 张卡片常驻 `will-change`，不因轮询不断创建动画实例。
- 快速切换分类、开关详情和切换源时，最终状态以最近一次操作为准。旧查询或退场回调不能关闭刚重新打开的详情，也不能短暂显示上一个源的数据。
- 按用户系统的 `prefers-reduced-motion` 使用共享组件的降级行为：取消弹窗位移/缩放及披露运动，并跳过退出等待；状态、焦点和可访问性仍正确。
- 功能中如确需补充共享组件未覆盖的运动，先检查 Skills 对应交互和现有公共实现，扩展共享能力并覆盖两处，避免 RSS 自行分叉。本期无需新增动画依赖。

### 6.3 动效验收方法

静态截图只能证明布局，不能替代以下动态验证：

1. 在相同主题、窗口宽度和系统动效设置下，对照 Skills 与 RSS：卡片反馈、分类选择、详情打开、详情关闭。
2. 抽取进场开始/中间/结束及退场中间/结束的帧，确认遮罩、位移、缩放、时长、曲线与共享基准一致，关闭时不存在内容提前清空。
3. 验证连续打开/关闭、退出中重新打开、快速切换分类、详情内切换 Tab、编辑后返回和后台刷新；页面与详情均不闪烁、焦点不丢失、没有重复入场。
4. 单独在普通动效和减少动态效果下验证；视觉回归若为截图稳定性关闭动画，必须另保留普通动效运行的行为测试。
5. 使用 200+ 合成源验证筛选和轮询，不出现逐卡累计延迟或动画期间阻塞输入；运行已有 `npm run motion:check` 并记录结果。
