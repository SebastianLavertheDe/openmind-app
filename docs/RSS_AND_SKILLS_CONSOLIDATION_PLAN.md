# RSS 与 Skills 收敛到 OpenMind 的修改计划

日期：2026-10-27（Asia/Shanghai）

状态：范围已确认，待实施。本次只新增计划文档。

将 `cctools-skills` 与 `blog-rss-feed` 的功能源码迁入 `openmind-app`，由当前项目统一构建、分发和维护。用户通过 App 管理信息源、设置总结和选题偏好，在本机完成 RSS 转换、更新、文章采集和后续处理。除明确移除的 `knowledge-wiki-compiler` 外，其余 Skills 全部迁入。

## 1 已确认的范围

| 编号 | 要求 | 完成标准 |
| --- | --- | --- |
| R1 | 两个外部项目收敛到当前项目 | 单独检出和安装 App 即可获得相关代码；构建和运行不再依赖这两个仓库的检出目录、Git 安装地址或它们发布的 RSS 文件 |
| R2 | 提供完整 RSS 源管理界面 | 全部源可见；网站转换型显示原网站地址，直接订阅型显示原 RSS 地址；子 OPML 中的源逐条展示 |
| R3 | 支持添加、删除、启用、停用 | 所有操作真正影响后台任务；删除后升级或重启不恢复，停用后不继续更新和采集 |
| R4 | 统一生成本地 RSS 并说明转换错误 | 沿用 `blog-rss-feed` 的标准 RSS XML 输出；用户提交链接后获得检测结果，失败时显示可理解的原因 |
| R5 | 本地定时更新 RSS 和拉取文章 | 应用内调度与系统 crontab 入口使用同一套执行逻辑；系统 crontab 可在 App 窗口关闭后运行 |
| R6 | 用户填写总结与选题偏好 | 提供持久化文本输入框；摘要、帖子筛选、选题排序实际使用该配置，修改后缓存和重新生成行为正确 |
| R7 | 移除知识库生成 Skill | 不迁入、不分发、不再默认调度 `knowledge-wiki-compiler`；其余 Skills 完整迁入 |

本方案采用用户于 2026-10-27 确认的新仓库边界，替代此前“两个仓库独立维护、App 不收录其源码”的约定。实施时同步更新 `AGENTS.md`、README 和相关架构文档。用户内容、密钥、登录状态、缓存和生成产物仍属于私人数据，不能进入源码仓库。

原两个仓库可保留历史；本计划不包含删除或归档远程仓库。App 自建 Skill 和通用 Git／目录／ZIP 导入能力继续保留。

## 4 RSS 源管理界面与数据模型

### 4.1 页面与交互

增加直接可达的“RSS 源”页面，沿用现有导航体系；每日简报页提供管理来源的入口。已安装 Skill 详情中的 RSS 配置入口复用该功能，避免两份列表和两套保存逻辑。

列表至少展示：名称、原始地址、源类型、启停状态、最近成功更新时间、最近错误和操作。支持搜索、状态筛选、新增、编辑、删除、启用、停用、立即更新，保留现有 OPML 导入能力。

- 网站转换型只显示网站或栏目原地址；本地 XML 路径和旧 GitHub 中转链接不作为用户的订阅地址。
- 直接订阅型显示用户使用的原始 RSS／Atom 地址，即使内部生成了另一份 RSS XML。
- 子 OPML 导入后展开为独立源，保留分组信息；能够逐条操作公众号等子源。
- 批量操作复用单源校验和更新逻辑，结果包含成功项和失败项。
- 新用户可以浏览全部预置源，默认不启动采集；选择需要的源并启用任务后开始运行。旧用户保持已有启停状态。
- 保存偏好、添加源和查看列表不自动启用定时任务。

复用 `Input`、`Textarea`、`SearchInput`、`Select`、`Button`、`IconButton`、`FormDialog`、`ConfirmDialog` 和现有启停控件。固定样式遵循 [UI 组件契约](UI_COMPONENT_CONTRACT.md) 与 [样式归属规则](../renderer/src/styles/README.md)，功能 CSS 只负责布局。

### 4.2 源配置契约

| 字段 | 用途 |
| --- | --- |
| `id` | 稳定源 ID；修改名称或地址不会重新分配身份 |
| `name` | 用户可编辑的展示名称 |
| `inputUrl` | 用户提交的原始网站或 RSS 地址 |
| `kind` | `website` 或 `feed`，决定展示和处理方式 |
| `resolvedFeedUrl` | 自动发现或重定向后实际请求的 Feed 地址，可为空 |
| `adapterId` | 使用的内置转换器；直接 RSS 使用通用转换器 |
| `enabled` | 用户启停状态，所有执行入口共同遵守 |
| `presetId` | 可选的预置源身份，用于更新映射与删除抑制 |
| `revision` | 并发修改检测；任务提交结果前校验配置是否已变化 |
| `group`、`tags` | 保留导入分组和用户分类 |
| `lastAttemptAt`、`lastSuccessAt`、`lastError` | 更新状态和可理解的失败信息 |

配置文件包含 `schemaVersion`、初始化标记和已删除预置源的记录。空订阅列表也是有效配置，不能按“缺少配置”重新灌入全部默认源。

以归一化地址和已确认的旧源映射去重；保留会改变 Feed 内容的路径、查询参数及大小写语义，不通过粗暴删除查询参数合并源。修改 URL 时检查与已有源的冲突。

### 4.3 新增、停用与删除语义

新增源先检测链接和转换能力，再保存。候选 Feed 不唯一时显示候选项供用户选择；失败保留输入和原因，便于修改后重试。

停用会取消未开始的源任务，并请求正在执行的任务停止；提交产物前再次检查源状态，防止停用后的结果重新进入文章采集。两阶段任务都必须检查状态，不能只在界面上变灰。

删除源取消未来任务，移除活动订阅并记录默认源删除状态。删除确认说明已经保存的文章、摘要和选题继续保留；历史内容清理属于独立操作。旧任务返回时不得重建已删除的源。

## 5 链接识别与本地 RSS 转换

### 5.1 识别顺序

1. 校验 HTTP／HTTPS 链接，并尝试读取资源。
2. 若内容是 RSS 或 Atom，使用通用转换器归一化为 RSS。
3. 若内容是网页，检测页面声明的 Feed 链接；处理重定向后的相对地址。
4. 若没有可用 Feed，匹配已迁入的网站转换器，必要时使用现有浏览器运行时。
5. 无法找到适配方式时返回“不支持该页面或未找到文章列表”，不把普通 HTML 当作转换成功。

迁入现有适配器覆盖的能力；新增任意网页不保证自动适配成功。首版不把“根据任意网页自动编写并执行爬虫代码”作为依赖功能。

逐项检查生成器中的固定 AI 过滤规则。网站本身提供的 AI 专栏保留其栏目含义；通用网站适配器中的个人兴趣筛选移到用户偏好阶段，避免内容在摘要前已被固定规则丢弃。

### 5.2 输出规范

统一使用 RSS 2.0 XML，保留来源名称、网站链接、原文链接、标题、发布时间、稳定 GUID、摘要及可用正文。Atom 输入同样转换。OPML 只负责订阅集合的导入导出，不承担文章缓存。

本地文件按 `sourceId` 存储，由程序读取，不要求启动 HTTP 服务，也不要求推送 GitHub。输出要求包括：

- 相对原文链接转换为绝对地址；GUID 在同一条目多次同步时稳定。
- 时间包含明确时区；无法取得发布时间时保留抓取时间的区别，不伪造原站发布时间。
- 文件写入采用临时文件、结构验证和原子替换，失败保留上一份有效结果。
- 正常没有新增文章与抓取／解析失败分别记录，失败不能覆盖为一份伪成功的空 Feed。
- 支持按源去重和更新判断；HTTP 缓存信息可减少重复请求，但不能跳过源启停检查。

### 5.3 错误反馈

| 情况 | 用户提示方向 |
| --- | --- |
| 地址格式不合法 | 链接格式不正确，请填写网站或 RSS 地址 |
| DNS、连接或超时失败 | 暂时无法访问该网站，可稍后重试 |
| HTTP 401／403、登录页或验证页 | 网站需要登录或限制访问 |
| Feed 格式损坏 | 无法解析该 RSS 内容 |
| 网页未发现 Feed 且无适配器 | 尚不支持此页面，或未找到文章列表 |
| 网站结构变化 | 已有转换规则无法读取当前页面 |
| 本地写入失败 | 无法保存同步结果，请检查数据目录 |

错误契约提供阶段、稳定错误码、简短消息和是否可重试。详细诊断进入运行记录；界面不直接展示 Python 堆栈或凭据。添加时反馈与定时失败记录使用同一套错误分类。

## 6 本地任务与系统 crontab

### 6.1 两个采集阶段

| 阶段 | 输入 | 输出 |
| --- | --- | --- |
| 更新源 `sync` | 启用的原网站／原始 RSS | 本地标准 RSS 文件及同步状态 |
| 拉取文章 `collect` | 上述本地 RSS 的新条目 | 已保存的文章、附件和采集去重状态 |
| 总结与选题 | 已保存内容、用户偏好 | 每日摘要与选题产物 |

`sync` 和 `collect` 可分别运行，也可以通过 `pipeline` 顺序执行。默认完整采集先更新源，再采集成功更新或明确有效的本地内容；使用旧缓存时记录其时间，不能将更新失败显示成全链路成功。

RSS 更新、文章采集、每日总结和选题有各自的任务设置。用户可以只采集文章，也可以仅生成阅读摘要。调整现有 `rss-to-summary-workflow`，避免每次更新订阅都隐式强制执行创作选题。

### 6.2 调度与命令入口

复用现有 `AutomationScheduler`、`AutomationRepository` 和执行设施，支持手动执行、间隔、每日时间和 cron 表达式。任务时区明确保存，界面展示下一次运行时间；新任务按用户当前时区初始化，迁移旧任务时保留原时区和时间语义。

提供不创建桌面窗口的命令入口。以下是计划中的命令形态，尚不是可执行接口：

```text
openmind rss sync --root <内容根> --user-data <应用数据目录>
openmind rss collect --root <内容根> --user-data <应用数据目录>
openmind rss pipeline --root <内容根> --user-data <应用数据目录>
openmind brief generate --date YYYYMMDD --root <内容根> --user-data <应用数据目录>
```

命令通过 Main 共用的服务与运行时执行；读取同一份订阅、偏好、安装状态和任务记录，不额外维护一份 cron 配置。入口在桌面初始化前分流，必须在无显示服务的 Linux 环境验证，不能以隐藏窗口代替无界面支持。

系统 crontab 可以调用完整采集或摘要命令，不依赖 App 窗口和应用内调度器常驻。提供安装后可使用的命令路径和引号示例；Windows 保留相同无界面命令能力，不假设存在 crontab。

RSS 更新与普通采集不要求配置大模型；需要总结、选题或其他 AI 能力时复用已配置的 Process Provider。无交互环境无法取得凭据或运行时依赖时，给出明确错误和非零退出码，不等待弹窗。

### 6.3 并发、去重与失败恢复

- 应用内调度、手动任务和系统 crontab 使用按内容根及源划分的同一套执行锁。现有调度器 leader 锁不能替代实际任务锁。
- 默认重叠运行跳过并记录原因；不同源可有限并发，同一源避免同时替换 XML 或提交采集游标。
- 条目去重使用稳定 GUID 与规范化原文链接，重启和重试不重复保存；成功保存内容后再推进游标。
- 原文更新与新文章分别处理；用户已经编辑的本地正文保留，更新内容通过既有版本或明确提示呈现。
- 配置修改采用版本检查；任务冻结本次配置，产物提交时检查源是否已停用、删除或替换。
- 单源失败不会阻止其他源；批次结果区分成功、部分失败、失败和跳过。
- 使用同一份运行记录展示更新数量、采集数量、失败阶段和最近成功时间；终止或崩溃后可以恢复，不能留下永久运行中的状态。

开发阶段不直接改写用户当前 crontab。迁移交付中列出旧命令的替换方式；旧仓库脚本不受新任务锁控制，切换时必须停掉重复的旧任务。

## 7 用户总结与选题偏好

在每日简报／选题相关设置中提供共享 `Textarea`，填写“希望关注什么、排除什么、如何总结和选择”。保存操作独立于生成操作，展示保存结果并提供明确的重新生成入口。

偏好配置至少包含 `schemaVersion`、`revision`、`text` 和 `updatedAt`。首次未填写时使用中性规则：忠实总结所选内容，按信息质量和时效组织，不默认要求 AI 领域、公众号风格或爆款潜力。原个人标准可以作为明确标注的可选示例。

示例：

> 关注产品设计和交互研究，优先选择有实际案例的内容，排除融资快讯。用中文简洁总结，每天推荐最多 10 条，并说明推荐理由。

执行链路必须同时覆盖：

1. `daily-article-summarizer` 的摘要要求和社交帖子初筛。
2. `daily-topic-selector` 的相关性判断、排序、数量、重点作者及输出要求。
3. 手动调用 `ai-media-topic-selector` 时的相同偏好上下文。
4. 引用这些结果的后续工作流，保持当前运行使用的配置一致。

清理所有不可配置的个人加分和领域排除规则，避免只修改最后一段提示词。事实忠实性、来源链接和不编造内容仍是公共要求，用户偏好决定选择与表达方式。

一次运行冻结偏好修订号；缓存 key 同时包含输入内容、模型、提示词版本和偏好摘要。偏好修改后不能直接复用旧筛选结果，也不能要求重新抓取原文才能重新总结。历史产物记录当时使用的偏好版本，用户明确重新生成时才按现有文档覆盖规则处理同日产物。

## 8 旧安装与用户数据迁移

### 8.1 订阅迁移

1. 识别当前内容根，备份待迁移配置并建立迁移记录。
2. 优先读取用户持久化 OPML；仅在其不存在且确属旧安装时回退到旧包内文件。读取引用的子 OPML，检测循环、缺失引用和重复源。
3. 合并旧 `source-settings.json` 中的名称、标签和停用状态；将旧 URL 派生 ID 映射到稳定源 ID。
4. 依据转换器定义、原 `rssUrl` 和受控的旧文件映射，恢复每个 `blog-rss-feed` GitHub 地址的原网站或原 RSS。
5. 保留用户修改过的地址；无法可靠恢复的条目标记为待配置，不猜测地址，也不把其他 GitHub 托管的合法 RSS 一概改写。
6. 迁移成功才提交新清单和初始化标记；后续只读取新配置。旧文件保留为恢复依据，不再双写。
7. 已初始化用户不会因新版预置源增加而自动被订阅；新推荐源由用户显式添加。维护删除记录，防止“删除后又出现”。

迁移可重复执行、可在中断后继续，成功后不重复追加源。文章缓存和旧内容需要结合 URL／GUID 映射，避免首次切换产生整批重复文章。

### 8.2 Skill 身份和任务迁移

对有来源记录且可确认是原默认集合的安装，建立旧包 key 到内置包 key 的映射。切换前停止或等待相关在途任务，内置包验证成功后再修改未来任务和依赖引用。历史 Run 的原 key、版本和摘要保留可读。

同 ID 的第三方包、用户修改过的包和来源不明的旧安装不能被自动覆盖或伪装成内置包；保留其身份并显示冲突处理入口。个人 Skill、已有 App 预设和无关任务不参与替换。

原默认开关中的 Git 安装／卸载逻辑改为本地内置能力管理。启用技能、订阅源和定时任务使用各自明确的状态；不能沿用“关闭默认集合就删除所有 App 技能”的实现。

迁移旧定时规则时保留启停、周期和时区，替换执行目标并清理重复的默认规则。用户自行创建的任务保留；无效目标明确标记，不能静默切换成另一个任务。

### 8.3 知识库生成 Skill 的退出

- 从打包清单、兼容矩阵、默认安装集合、展示入口、固定依赖和运行报告中移除 `knowledge-wiki-compiler`。
- 官方默认安装的该包退出当前维护集合；停止其托管的未来任务，卸载已确认归属的包代码及安装注册，避免遗留目录继续被发现和执行。
- 已有知识库内容、历史报告和运行记录保留，不因移除生成器而删除。
- 用户主动导入的独立副本按普通外部包管理，不通过 ID 匹配误删。引用它的自定义任务保留定义并标记不可用，供用户自行调整。

## 9 分阶段实施

各阶段以可验证结果结束；完整交付包含全部 15 个 Skill，不能在 RSS 页面完成后停止。

| 阶段 | 修改内容 | 阶段验收 |
| --- | --- | --- |
| P0 统一契约与迁入映射 | 固定包清单和源映射；定义源配置、偏好、错误、任务参数与旧身份迁移；更新仓库边界说明 | 每个旧包和每条源都有明确去向，知识库生成器明确排除 |
| P1 迁入源码与构建 | 收录 15 个包、共享模块及 Feed 转换代码；扩展 Agent／Process／Workflow 打包；接入运行时依赖 | 不存在相邻仓库时仍能构建、校验和安装所有内置包 |
| P2 源管理与转换后端 | 统一配置仓储、链接识别、网站适配器、本地 RSS、错误分类、增删改和状态生效 | 用固定样例验证直接 Feed、网页转换、失败及停用／删除行为 |
| P3 管理界面 | 完整列表、原地址展示、搜索、新增、编辑、启停、删除、同步状态和错误 | 在隔离用户目录中完成 UI 行为、样式和视觉验收 |
| P4 调度与无界面运行 | 接入 sync／collect／pipeline、任务设置、跨进程锁、运行记录及 crontab 命令 | App 与外部命令并发不重复；无窗口、无显示服务时可完成采集 |
| P5 偏好与生成链路 | 增加输入框、持久化、运行快照；修改全部相关筛选和缓存逻辑 | 两组不同偏好产生符合各自要求的筛选；无需重新采集即可重新生成 |
| P6 升级迁移与清理 | 切换旧订阅、安装身份、定时规则；清理旧仓库依赖和知识库生成器 | 迁移、重复迁移、中断恢复及旧数据保留通过；不恢复已删除源 |
| P7 打包与完整验收 | 在独立检出和安装包中检查 RSS 及其余所有迁入能力，更新使用说明 | 核心链路及全部保留能力可用，验证记录区分平台和真实外部服务范围 |

P0 必须先完成；P1 支撑后续运行。P2 完成后推进 P3 与 P4，P5 基于统一配置契约实施，P6 在迁入包和新流程可用后执行，P7 验证最终组合。

## 11 验证与交付标准

### 11.1 必须覆盖的行为

| 场景 | 验收要求 |
| --- | --- |
| 独立构建 | 只有 `openmind-app` 检出目录时，15 个迁入包和全部转换模块能构建、验证和分发；核心测试不因缺少外部仓库跳过 |
| 完整源清单 | 与迁入映射逐条核对；两边源集合合并去重，停用源可见，子 OPML 展开，无旧 GitHub 中转地址冒充原网站 |
| 新增与错误 | 覆盖 RSS、Atom、网页 Feed 发现、已有网站适配器、未知网站、超时、登录限制、错误 XML 和本地写入失败 |
| 启停与删除 | 手动、定时、CLI、嵌套导入源全部遵守状态；在途任务不会恢复已删除源；删除不影响已保存内容 |
| RSS 正确性 | XML 可解析，原文链接与 GUID 稳定，日期正确，失败保留有效缓存，空更新与失败可区分 |
| 定时与 crontab | 应用内任务和外部命令共同使用配置与执行锁；时区、重叠跳过、崩溃恢复和去重行为正确 |
| 用户偏好 | 覆盖非 AI 兴趣、排除主题、不同语言和条数要求；前置过滤不沿用旧个人规则；偏好修订使相关缓存失效 |
| 旧数据迁移 | 覆盖空清单、停用、删除、修改地址、损坏子 OPML、缺失引用、旧缓存、重复迁移和中断恢复 |
| 包身份与依赖 | 官方安装可迁移；同名第三方和用户修改包不被覆盖；历史记录可读；共享模块及跨包调用在安装后可用 |
| 知识库退出 | 新安装不含生成器，官方旧安装无自动入口；历史知识库内容保留；其他 15 个包逐项验证 |
| 真实界面 | 新用户与迁移用户均完成增删启停、错误重试、任务设置、偏好保存与生成；浅深色、窄宽窗口和键盘操作通过 |
| 安装包 | 无开发机绝对路径、相邻仓库依赖和真实私人数据；按支持平台验证 Python、浏览器和视频依赖 |

测试使用临时 `openmindRoot` 和 `userData`。RSS 转换优先使用固定 HTML／RSS／Atom 样例与本地测试服务，避免将公网变化作为常规测试前提；真实站点兼容性另行记录代表性验证结果。

偏好注入、源状态和缓存采用确定性测试；真实模型输出另行核对，不把 mock 通过当作真实模型质量通过。Linux 无显示服务运行和安装包验证必须实际执行，不能只验证开发模式。

### 11.2 检查命令

按阶段运行相关定向测试。最终至少执行仓库规定的以下检查，发布前再完成 `npm run verify`：

```bash
npm run typecheck
npm run lint:manifests
npm run check:ui
npm run visual:ui
npm run build
npm run test:unit
npm run test:integration
npm run test:e2e
```

视觉基线需显式评审并查看实际图、预期图和差异图。现有失败项先确认基线，再区分本次新增问题；不得通过忽略外部包测试、删除行为断言或自动重建基线掩盖问题。

### 11.3 最终交付物

- 一个可独立构建和安装的 App，包含迁入的 15 个 Skill 及 RSS 转换能力。
