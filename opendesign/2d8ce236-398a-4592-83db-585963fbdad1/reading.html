为什么 Prompt 在生产里会不稳定

content/notes/prompt-stability.md
标签
提示工程评估生产+ 加标签

同一个 Prompt，本地 demo 次次完美，接进产品就开始飘——这是 LLM 应用最普遍的体验落差。问题很少出在「模型不够强」，更多出在我们把哪些东西当成了「理所当然」。

三个最常被忽略的失稳来源

采样随机性

温度、top-p 在每一次调用里都是真随机。你在本地连跑十遍都对，不代表线上第十一次也对。凡是依赖「模型某次恰好按某种格式输出」的逻辑，都是在和概率对赌。

上游版本漂移

Provider 静默升级模型版本是常态。你绑的 gpt-4o-2024-08 某天被换成新的快照，行为就变了，而你的评估集不会主动告诉你。

把「模型版本」当作代码依赖来管理，而不是当作一个永不变的常量。

隐式格式依赖

最隐蔽的一类：你的解析代码假设模型「总是」先输出标题再输出列表，但 Prompt 里从没这么要求过。一个能复现的最小例子：

用户：总结这篇笔记
模型：## 摘要        ← 有时是「摘要：」有时是「## 摘要」
      - 点一
      - 点二        ← 有时会塞进一句开场白

解析一旦写死 split('## ')，遇到变体就崩。解法是结构化输出 + 容错解析，双保险。

怎么稳住

先让它可观测，再谈让它稳定。

  • 固定版本：显式锁定模型快照，把变更纳入发版流程。
  • 降随机：结构化任务用低温度 + 结构化输出，把随机性挤到不关键的环节。
  • 跑评估集：每次改动跑一遍离线集，盯通过率和回归，而不是凭手感。
  • 容错解析：永远假设模型会换格式，解析层做兜底。

这四条做完，Prompt 从「玄学」变成「工程」，稳定性才有据可循。
